# 视频生成API问题排查指南

## 当前问题：平台级限流

### API时长限制

视频生成API（豆包Seedance）对时长有严格限制：

| 参数 | 最小值 | 最大值 | 推荐值 |
|------|-------|--------|-------|
| duration | 4秒 | 12秒 | 6-10秒 |

**重要说明**：
- 单条视频时长必须在4-12秒之间，超出范围会被API自动截断
- 推荐对话镜头使用6-8秒，无对话镜头使用8-10秒
- 如需更长视频，请在后期编辑器中拼接多个短视频

### 症状
- 所有视频生成请求立即返回403错误
- 错误信息：`"code":"ErrTooManyRequests"`
- 错误详情：`"message":"因触发限流调用内置集成失败，请稍后重试"`

### 原因分析

这不是API级别的限流（可以通过调整请求间隔解决），而是**平台级别的限流**：

1. **API配额已用完**：当前环境的视频生成API配额已经耗尽
2. **触发平台限流**：短时间内请求过多，触发了平台的保护机制
3. **服务限制**：某些服务可能未开通或已过期

### 解决方案

#### 方案1：等待平台重置配额（推荐）

平台限流通常是临时的，等待一段时间后会自动解除：

```typescript
// 建议等待时间：5-10分钟
// 然后重试生成
```

#### 方案2：检查API状态

访问测试接口检查当前状态：

```bash
# 检查API配置状态
curl http://localhost:5000/api/videos/test

# 测试视频生成
curl -X POST http://localhost:5000/api/videos/test
```

#### 方案3：联系平台管理员

如果限流持续存在，请联系平台管理员：
- 检查API密钥权限
- 确认账户配额状态
- 申请提升配额

### 已实施的改进

为了在未来避免触发平台限流，我们实施了以下改进：

#### 1. 全局任务调度器
- 令牌桶算法控制请求速率
- 滑动窗口统计API调用频率
- 自动降级机制
- 详见：`src/lib/video-scheduler.ts`

#### 2. 智能限流控制
- API层：最小间隔30秒，403错误后等待60秒
- 前端层：重试时递增等待30s/45s/60s...
- 平台级限流：立即停止，不重试

#### 3. 错误处理优化
- 区分平台级限流和API级限流
- 提供明确的错误信息和建议
- 避免无效重试浪费配额

### 限流策略对比

| 限流类型 | 触发原因 | 解决方案 | 等待时间 |
|---------|---------|---------|---------|
| API级限流 | 单个请求过快 | 调整请求间隔 | 30-60秒 |
| 平台级限流 | 配额用完/触发保护 | 等待配额重置 | 5-10分钟 |
| 账户级限流 | 权限不足/服务过期 | 联系管理员 | 需要人工处理 |

### 如何避免未来触发限流

1. **使用均衡或稳定策略**
   ```typescript
   // 调用队列处理API时指定策略
   await fetch('/api/videos/queue/process', {
     method: 'POST',
     body: JSON.stringify({
       batchId: 'your-batch-id',
       strategy: 'stable', // 或 'slow'
     }),
   });
   ```

2. **批量生成时分批处理**
   - 不要一次性生成所有镜头
   - 每批生成3-5个，等待5-10分钟后再生成下一批

3. **监控生成状态**
   - 关注控制台的错误日志
   - 遇到403立即停止，不要继续请求
   - 等待足够时间后再重试

### 错误代码说明

| 状态码 | 错误类型 | 说明 |
|--------|---------|------|
| 200 | 成功 | 视频生成成功 |
| 401 | 认证失败 | API密钥无效或过期 |
| 403 | 权限拒绝 | 限流或权限不足 |
| 403 + ErrTooManyRequests | 平台限流 | 配额用完，需等待 |
| 429 | 请求过快 | API级限流，稍后重试 |
| 500 | 服务器错误 | 服务异常，稍后重试 |
