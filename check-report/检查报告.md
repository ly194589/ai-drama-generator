## 二、发现的问题（按严重度）

### 高风险 · 安全

1. **身份完全由客户端头决定，无签名校验。**
   `src/middleware.ts:60-66` 只要请求带任意 `x-user-id` 或 `authorization` 头即放行；`src/lib/api-client.ts` 从 localStorage 取值设头；`src/lib/user-token.ts:49` 的 Bearer 解析仅 base64 JSON、不验签。任何人可伪造他人或管理员身份（`ADMIN_USER_IDS` 含 `admin`、`dev_user`）。
2. **多个写/删接口缺少 user_id 归属校验（IDOR，可跨用户删除）。** 与问题 1 叠加后，伪造任意身份即可删除他人数据：
   - `DELETE /api/images`（批量，route.ts:90）与 `DELETE /api/images/[id]`（:60）
   - `DELETE /api/audio/[id]`（:55）
   - `DELETE /api/videos/[id]`（:102）
   - `DELETE /api/chat/sessions/[id]`（:26）
   - `DELETE /api/drama/series/[id]`（:389）、`.../scenes`（:68）、`.../artwork`（:1334）
   - `POST /api/images`、`/api/videos`、`/api/audio` 上传不校验登录态、插入记录不写 `user_id`，数据无法隔离。
   （对照：`/api/drama/series` GET/POST、`/api/zhipu/voice-clone/[id]` 等有正确的 401 + 归属校验，可作修复模板。）
3. **LLM 流式接口匿名可用。** middleware 白名单含 `/api/chat/stream`、`/api/chat/advisor`，未登录即可消耗模型配额。

### 中风险 · 环境/配置

4. **本地缺 `COZE_SUPABASE_URL` / `COZE_SUPABASE_ANON_KEY`（无 .env）。** 所有依赖数据库的 API 返回 500（服务端日志确认 `COZE_SUPABASE_URL is not set`），登录/注册/卡密/素材等登录后数据路径无法在本地端到端验证。属环境缺失而非代码缺陷；错误未向客户端泄露堆栈，处理得当。
5. **`scripts/dev.sh` 端口硬编码。** `PORT=5000` 且 `next dev --port $PORT` 忽略 `DEPLOY_RUN_PORT` 覆盖，违反 AGENTS.md 端口约定；清端口用的 `ss` 为 Linux 命令，Windows 下无效。
6. **多处 `http://localhost:5000` 兜底硬编码**（OAuth 回调、payment、videos 队列自调用，共 10 处）。换端口部署时自调用与回调会指向错误地址。

### 低风险 · 规范

7. `src/app/login/page.tsx:823` 硬编码 hex `bg-[#1677FF]`。
8. Tailwind 原生色盘使用 1028 处（`text-green-500` 等）+ `bg-black/white` 350 处，与「语义变量」约定不符（多为渐变装饰，首页紫粉渐变即属此类）。
9. 部分 `<img>` 缺 `loading="lazy" decoding="async"`：drama/page.tsx 8204、8351、10493；storyboard/page.tsx 421、454；images/page.tsx 1524。部分 `<video>` 缺 `preload="metadata"`：drama 8606、editor 383/412。
10. `X-Frame-Options` 不一致：next.config.ts 设 SAMEORIGIN，middleware 对页面覆写为 DENY。

## 三、建议

1. 优先修高风险 1+2：middleware 改为校验签名 token（或平台网关注入的可信头），所有写/删接口补 `user_id` 归属过滤，上传接口补 401 与 `user_id` 写入。
2. 将 `/api/chat/stream`、`/api/chat/advisor` 移出匿名白名单或加配额校验。
3. 配置本地 `.env`（Supabase 凭据）后复跑登录后数据路径的端到端验证。
4. dev.sh 改为 `--port ${DEPLOY_RUN_PORT}`；localhost:5000 兜底统一改读 `DEPLOY_RUN_PORT`。
5. 规范类问题可批量清理（hex、lazy/preload、色盘），不影响功能。
